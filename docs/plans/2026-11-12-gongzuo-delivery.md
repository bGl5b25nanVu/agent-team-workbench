### 团队与工作协议

| 角色 | 主要职责 | 默认探索 |
|---|---|---|
| 总管 / Coordinator | 澄清目标与验收条件、拆解阶段、分派任务、核对交接、汇总交付 | 有限探索 |
| 研究员 / Researcher | 查证来源、区分事实与推测、解释不确定性、提出有证据的建议 | 有限探索 |
| 工程师 / Engineer | 实现功能、集成修改、处理缺陷、提交可复现的验证记录 | 有限探索 |
| 设计师 / Designer | 设计流程、交互状态与视觉方案，检查实现后的体验 | 开放探索 |
| 测试员 / Tester | 独立验证、提出反例、报告可复现缺陷与覆盖边界 | 有限探索 |
| 运营 / Operator | 整理文档、使用说明和交付材料，在已有授权内准备发布 | 稳健执行 |

三种模板分别选择研发 6 人、研究 4 人、内容 4 人。三档探索方式写入可编辑指令：稳健执行遵循既定路线；有限探索比较最多两个方案；开放探索提出三个方向后验证并收敛。

完整角色指令、团队公约、交接格式、验收规则、返工与升级约定保存在 [运行协议](2026-11-12-agent-team-workbench.md)，并作为共享预设进入真实成员配置。

### 实际行为

- 向导支持姓名、职责、模型或本地 CLI 来源、完整指令、探索方式、权限预设、目录、形象及复用成员。
- 新团队成员保存为待命状态。创建团队、重复同一请求、修改配置不会触发欢迎或任务模型调用。
- 首个 Goal 启动协调者；其他成员收到有效委派或直接消息后才运行。
- 每个新团队成员分派前核对其精确模型路由，并向实际接收任务的 Session 应用有效权限。模型消失、选型失败或权限应用失败时停止该任务，不静默回退。
- 持久创建记录保存已知成员和群 ID。同一操作 ID 去重；已知部分失败可继续；未知结果保留回执并停止自动重试，不声称所有外部副作用绝对只发生一次。
- 工作台读取真实 Goal、阶段、任务和成员状态。待办中心读取真实问题与审批，并遵守实际可回答状态。

因此没有实际实现截图、没有冒充运行截图的概念图，也没有声称逐像素一致。详细证据、目标视口与剩余验收步骤见 [design-qa.md](../../design-qa.md)。该文件状态为 `blocked`。

### 约束的准确边界

恢复 Git bundle 的示例：

```sh
git clone -b feat/team-workbench Gongzuo-history.bundle Gongzuo
cd Gongzuo
git remote set-url origin https://github.com/bGl5b25nanVu/agent-team-workbench.git
```

最后一步需要本机已有 GitHub 推送授权。后续 PR 应以 fork 的 `dev` 为目标分支，不覆盖 `main`，不强制推送。
